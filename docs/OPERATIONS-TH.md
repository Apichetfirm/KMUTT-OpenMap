# การดูแลและกู้คืน KMUTT OpenMap

10 พฤศจิกายน 2569 · Initiated by Firm Impulse · FIBO FRAB11

## โครงสร้างและเจ้าของงาน

เว็บเป็น static site ข้อมูลเผยแพร่อยู่ใน Git; ไม่มีฐานข้อมูลส่วนกลางหรือ endpoint รับรายงานอัตโนมัติ ข้อเสนอในเบราว์เซอร์อยู่ใน localStorage ของเครื่องและ origin นั้น การเตรียม GitHub Issue ต้องให้ผู้ใช้ตรวจและส่งเอง การล้าง browser storage เปลี่ยนเครื่อง หรือเปลี่ยน origin อาจทำให้เข้าถึงข้อเสนอเดิมไม่ได้

กรอกทะเบียนต่อไปนี้ก่อนรับดูแลจริง อย่ากรอกรหัสผ่าน/token ลงในเอกสาร:

| รายการ | เจ้าของ/ผู้สำรอง | ตำแหน่งหรือ URL | ค่าใช้จ่าย/วันต่ออายุ |
| --- | --- | --- | --- |
| Repository และ review | รอแต่งตั้ง | https://github.com/Apichetfirm/KMUTT-OpenMap | ตรวจตามบัญชีองค์กร |
| GitHub Pages/Actions | รอแต่งตั้ง | Settings → Pages / Actions | ตรวจโควตาและแผนบัญชี |
| โดเมนเสริม หากมี | ยังไม่ยืนยันว่ามี | รอเจ้าของยืนยัน | รอเจ้าของยืนยัน |
| ผู้ให้บริการแผนที่ | ผู้ดูแลโค้ด | tiles.openfreemap.org | ตรวจเงื่อนไขล่าสุด; ไม่ใช่ SLA ของโครงการ |
| เจ้าของข้อมูลและ reviewer | รอแต่งตั้ง | ช่องทางที่ทีมเลือก | รอบตรวจข้อมูล |
| ที่เก็บหลักฐานส่วนตัว/สำรอง | รอแต่งตั้ง | พื้นที่จำกัดสิทธิ์ที่ทีมเลือก | ระยะเก็บที่ทีมกำหนด |

บัญชีและสิทธิ์ GitHub ให้เจ้าของเชิญผู้รับช่วงผ่านบัญชีของผู้รับเอง ตรวจว่าเข้าถึง repository, Actions และ Pages ได้จริงก่อนถอดสิทธิ์ผู้ดูแลเดิม

## ปล่อยรุ่น

1. สร้าง branch แก้โค้ด/ข้อมูล พร้อมหลักฐานที่เผยแพร่ได้ และปรับเอกสารสถานะ
2. รัน `npm ci && npm run verify` แล้วทดสอบ browser และ Python/audits ตามคู่มือรับมอบ
3. เปิด PR ตรวจ diff ของข้อมูล สิทธิ์สื่อ และผล CI ที่ตรงกับหัว branch
4. หลัง merge เข้า main: Pages เรียก reusable CI รอการทดสอบเต็มก่อน job deploy เริ่ม งานตรวจล้มเหลวต้องหยุด deploy
5. หลัง deploy รัน `scripts/verify-production.mjs` จาก workflow เดิม ซึ่งตรวจไฟล์จริงเทียบ SHA-256 และ interaction จริง เก็บ artifact `production-smoke-<SHA>`
6. ตรวจผล workflow ทั้งสถานะ deploy และ smoke เพราะ smoke ที่ล้มหลัง deploy หมายถึงผู้ใช้ได้รับรุ่นนั้นแล้ว ต้องตรวจแก้หรือ rollback ทันที

Manifest ตรวจความครบถ้วนภายในชุดได้ แต่ไม่แทนการอ่านหลักฐานหรือพิสูจน์สิทธิ์ข้อมูล หากแก้ไฟล์และ manifest พร้อมกันก็สร้างชุดใหม่ได้ จึงต้องอ้าง commit/ผู้จัดส่งที่เชื่อถือได้

## สำรองและกู้คืน

- หลังรุ่นที่ยอมรับ: เก็บ source archive, built site, manifest, `SHA256SUMS`, ผลทดสอบ และ SHA ไว้ในพื้นที่ทีมอย่างน้อยสองแห่งตามนโยบายองค์กร
- รักษาข้อมูล public canonical ใน Git; แยกต้นฉบับภาพ ใบอนุญาตและหลักฐานที่มีข้อมูลส่วนตัวไว้ในพื้นที่จำกัดสิทธิ์
- ให้ผู้มี local draft ส่งออก JSON ผ่านหน้าเว็บก่อนเปลี่ยนเครื่อง ล้าง browser หรือ rollback และเก็บไฟล์อย่างเหมาะสม อย่าอ้างว่าสำรองของ Git ครอบคลุม localStorage
- ทดลองกู้คืน: แตกชุดในโฟลเดอร์ใหม่ → `sha256sum -c SHA256SUMS` → `node source/scripts/verify-site.mjs site` → เปิดด้วย loopback server → ค้น N9/N10/N16 และทดสอบแชร์/ข้อมูล
- ทดลอง rebuild source ด้วย `npm ci && npm run verify` ในโฟลเดอร์แยก; source ZIP ไม่มี Git metadata จึงอาจ build manifest ที่ source_commit เป็น null ได้ ให้เทียบต้นทางกับ `HANDOFF.json`
- ไม่มีการนำเข้า draft สำรองอัตโนมัติที่รับรองในคู่มือนี้ ให้เก็บ JSON ต้นฉบับและใช้กระบวนการตรวจ PR เมื่อจำเป็น

## Rollback

ตรวจว่า regression เริ่มจาก commit ใด เก็บ log/screenshot และส่งออก draft ก่อน จากนั้นสร้าง branch เพื่อ revert commit ที่ผิด เปิด PR พร้อมผลทดสอบ และ merge ตามกระบวนการปกติ การ push main ใหม่จะผ่าน gate/deploy/smoke เดิม ห้าม force-push ลบประวัติ ห้ามเปลี่ยนข้อมูล candidate เป็น verified เพื่อให้ตรวจผ่าน

หาก hosting ล้ม ให้คืน built site รุ่นที่ตรวจรับแล้วผ่านขั้นตอนของ hosting โดยคง URL/base path และเครดิต ตรวจ manifest กับ HTTPS smoke ก่อนประกาศกู้คืน การคืนข้อมูลเซิร์ฟเวอร์ไม่ได้คืน localStorage ของผู้ใช้

## รับมือเหตุขัดข้อง

| อาการ | ตรวจเบื้องต้น | การแก้/ยืนยันผล |
| --- | --- | --- |
| หน้าไม่ขึ้น/404 | Pages workflow, base path, index.html | ตรวจ deploy URL และ published bytes; ถ้าเป็น regression ให้ revert |
| แผนที่ว่างแต่ค้นหาได้ | เครือข่าย provider, WebGL2, console/CSP | ใช้ directory ต่อได้ กด retry; แยก provider ล้มออกจาก data/module ล้ม |
| ค้นหาไม่ได้/ข้อมูลโหลดล้ม | `data/buildings.json`, HTTP status, validate-data | ทบทวนรุ่น/ไฟล์และ build ใหม่; อย่าเดาพิกัดแทน |
| บันทึกข้อเสนอไม่ได้ | storage quota/สิทธิ์, HTTPS/Web Locks, หลายแท็บ | ส่งออก JSON ปิดแท็บซ้ำและตรวจ revision; อย่าล้าง storage ก่อนเก็บข้อมูล |
| ข้อมูลสถานที่ผิด/ทางปิด | แหล่งหลักฐาน วันที่ สถานที่จริง | ทำเครื่องหมายและแก้ผ่าน review; ข้อมูลเดินทางเร่งด่วนให้ตรวจจากมหาวิทยาลัย |
| audit/CI ล้ม | advisory, lockfile, browser log | แก้ต้นเหตุแล้วรันใหม่ครบ ห้ามปิดตรวจหรือเปลี่ยนผลเป็นผ่าน |
| smoke หลัง deploy ล้ม | asset hash, runtime, provider, screenshot | ระบุผู้ใช้ได้รับผลหรือไม่ แก้หรือ revert และตรวจบนเว็บจริงซ้ำ |

## งานประจำที่เสนอให้ทีมยืนยัน

ทุกครั้งที่แก้: verify + CI + review หลักฐาน; ทุกครั้งที่ปล่อย: smoke จริงและ backup; ทุกเดือน: ทบทวน dependency/action pins/provider และสิทธิ์ผู้ดูแล; ทุกภาคเรียน: ตรวจข้อมูลอาคาร บริการ เวลาเปิด และความสะดวกของผู้ใช้; หลังงานก่อสร้าง/ย้ายหน่วยงาน: ตรวจตำแหน่งและเส้นทางที่ได้รับผลทันที

ระบบยังไม่มีบริการ monitoring ภายนอกหรือ SLA ที่ตั้งให้ใหม่ ให้ผู้ดูแลเลือกช่องทางแจ้งเหตุและรอบตอบสนอง พร้อมทดสอบการแจ้งเตือนก่อนระบุว่ามีผู้เฝ้าระบบตลอดเวลา
