# University collaboration and student handover

Initiated by Firm Impulse · FIBO FRAB11. This project does not claim official endorsement.

Facilities, library, accessibility, faculty and campus-service staff can help without authorizing deployment or exposing restricted plans. Provide public information with a responsible department, effective/source date, public source link and explicit redistribution permission/license. A current name or floor count does not automatically verify a location, entrance, height or accessible route.

| Needed information | Suggested owner | Review acceptance |
| --- | --- | --- |
| S1/S2/S6/N19 identity/history | BGM / official campus-directory owner | Written current codes/names; explain conflicting button/image labels and date; no inferred dormitory demographics |
| 35-code footprint associations | Facilities GIS staff + independent campus reviewer | Licensed polygons and per-code rationale/version/date; resolve complexes/annexes; review overlap and uncertainty |
| Public entrances | Facilities + student survey team | Separate surveyed points, dates/reviewers, opening/access conditions and graph node links |
| Heights / floor counts | Building office | Measured metres with evidence, or documented floors explicitly separated from an estimated render height |
| Paths and accessibility | Facilities + accessibility office + two reviewers | Actual public connectivity, crossings, gates/hours, ramps/slopes/surfaces and passage evidence; independent accessible-route audit |
| Services and hours | Service operators / student affairs | Current public names/locations, schedules, exceptions/holidays and observation dates; verify closures |
| Mobile QA | Student maintainers | Chrome/Firefox/Safari and physical Android/iOS; load time, interaction, GPS denial, memory/thermal behavior and mid-range Android FPS |

Staff can submit a reviewed JSON package or a GitHub issue using the same public contribution form. Institutional identity alone does not authorize private-plan redistribution. Project maintainers verify correspondence, source permissions and evidence separately, retain history and request an independent PR review. Field verification requires a documented survey and independent reviewer. No submission automatically changes the map.

A future student maintainer should first run the README checks, read DATA-MODEL.md and the complete handoff, and review the unresolved building queue. Update canonical data in a feature branch, regenerate derived views, run geometry/unit/browser checks, capture live screenshots and request review. Never replace an unknown with a plausible guess to improve coverage counts. Keep the initiator attribution and separate licenses.

Deployment uses the existing main-only Pages workflow after review. Feature branches do not deploy production. No major release is approved by the implementer. Report security concerns using SECURITY.md; avoid posting credentials or sensitive details in public issues. Rotate maintainers through documented roles rather than relying on one graduating contributor.
